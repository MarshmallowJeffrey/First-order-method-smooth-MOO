## 1. 实验名字

K=2 认证模式下的帕累托前沿对比:均匀网格基线(论文算法 1)对
自适应束方法(论文算法 2),运行在 without-256-checkpoints 测量
轨道上。

## 2. 实验内容——比的是什么样的帕累托最优

问题有两个按类的交叉熵损失 F1、F2,都要**最小化**。每种方法完成
各自的认证运行后,对 t 在 [0,1] 上 1,001 个取值的每个权重
λ = (t, 1−t) 回答同一个问题:"这个权衡下你交付哪个点?"两种方法用
**同一条交付规则**回答——在自己的点集中取 ‖∇F_λ‖² 最小的那个点
(自适应方法用束里存好的梯度,基线用运行后对每个网格节点做的一次
求值;任何地方都没有重新优化)。随 t 扫过,把交付点的 (F1, F2)
画出来,就是每种方法的**经验前沿**:它实际能递给你的权衡菜单。

所以比较的**不是**问题的真实帕累托前沿(未知),而是交付前沿对
交付前沿,评判标准:

- **支配关系**:两个轴都是损失,越靠左下越好。一条前沿若位于另一
  条的左下方,就在每个 F1 水平上给出更好的 F2(反之亦然)。
- **分辨率/光滑度**:前沿有多少个不同的点、把权衡范围覆盖得多均匀
  ——网格方法只能用它 r+1 个节点解中的一个来回答。
- **认证成本**:两种方法都跑认证模式;证书花了多少、以及到底拿没
  拿到。

各方法的认证语义:自适应方法在它自己的 λ 搜索值满足
max_λ min_i ‖∇F_λ‖² ≤ 2ε/3 时停止。基线用 7 月 8 日加入的认证
模式:节点在自己权重下满足 ‖∇F_{λ_i}‖² ≤ node_tol 即"已服务",
全部节点达标即停。它的 ε 在范数空间里拆成两份:node_tol = ε/4
(一半范数预算给节点),另一半留给节点之间的网格退化 h·D
(h = 1/(2r),D = 交付点处 ‖∇F1 − ∇F2‖);运行后按
(√节点值 + h·D_i)² 逐节点精确审计全 λ 证书。

要求的两个组合:(1) 基线 ε 0.01 对 自适应 ε 0.01;
(2) 基线 ε 0.01 对 自适应 ε 0.001(基线两个组合共用同一次运行,
它的 ε 相同)。

## 3. 参数设置

问题实例(所有运行完全相同):K=2,p=20,n=50,000,
hidden_sizes=[96,96](d = 11,522),activation=tanh,数据种子 7,
初始化种子 8,W* ~ U[−1,1]。

方法参数:coarse_resolution r=10(主运行)/ r=20(复验,只影响
基线——自适应方法不使用 r,两个文件夹里它的运行逐位一致);
n_passes=100,000;steps_per_point_per_pass=5;max_grad_evals=2,000,
认证模式下作为**保险丝**(不是停止条件);两侧
eval_every_n_grads=153;max_outer=1,000,000;max_inner=5;
lambda_max_starts=8;prune_inner=True;plateau_window=4,
plateau_consecutive_windows=2。

认证参数:基线 ε 0.01 → node_tol = ε/4 = 0.0025;自适应
ε ∈ {0.01, 0.001},停止条件为自身搜索值 ≤ 2ε/3。

测量轨道:without-256-checkpoints(检查点记录各方法自己的最坏
情况值,不做外部 256 起点求解)。只影响墙钟时间和检查点曲线,
不影响轨迹和交付前沿。

## 4. 结果分析与结论

各运行结局(自适应结果在两个文件夹里完全相同):

| 运行 | 结局 | 成本 |
|---|---|---|
| 基线 ε 0.01,r=10 | **失败**:3/11 节点达标;审计全 λ 水平 3.57 | 烧完保险丝(2,000 梯度) |
| 基线 ε 0.01,r=20 | **失败**:5/21 节点达标;审计水平 3.81 | 烧完保险丝 |
| 自适应 ε 0.01 | **认证成功**(停止值 6.08e-3) | 132 梯度 = 保险丝的 6.6%,束 m=17 |
| 自适应 ε 0.001 | **认证成功**(停止值 6.63e-4) | 700 梯度 = 保险丝的 35%,m=71 |

前沿几何(双对数图在各运行文件夹里):

- **光滑度/分辨率——预期证实。**自适应前沿是密集光滑的曲线
  (ε 0.01 有 14 个交付点,ε 0.001 有 54 个);基线前沿是穿过它
  6 个(r=10)/ 8 个(r=20)节点的锯齿折线。
- **支配关系——在权衡内部区域证实。**凡两个损失都不极端的地方,
  自适应前沿都以明显的差距位于基线折线的左下方。仅有的例外是两个
  纯权重端点:基线的 t=0 / t=1 节点收敛到单目标最优,在**一个**轴
  上伸得更深,代价是另一个轴灾难性地大(如 r=10 的 t=1 节点:
  F1 = 0.041 而 F2 = 16.7)——端点节点的预期行为,不构成支配。
- **更严的 ε 买到更好的菜单。**ε 从 0.01 收紧到 0.001(梯度多
  5.3 倍),前沿从 14 点加密到 54 点,两端各深入约 3.5–3.8 倍
  (F1 最小值 0.033 → 0.0088,F2 最小值 0.032 → 0.0093)。

基线为什么无法认证(两层独立原因,都经过审计):

1. **网格份额过大(结构性)。**交付点处实测 D_max ≈ 6.1,于是仅
   网格项就有 (h·D)²:r=10 时 0.093,r=20 时 0.024——都超过
   ε = 0.01。在这两个分辨率下**任何 node_tol 都无法认证 0.01**;
   按公式,仅网格项达标就需要 r ≥ 31,对半分预算则需要 r ≈ 62。
   这是平台研究的"离散化地板"在认证语言下的重述。
2. **中间节点不收敛(健壮性)。**只有接近纯权重的端部节点通过
   node_tol(r=10 时 3/11,r=20 时 5/21);中间混合权重节点震荡
   (自身梯度 0.04–3.5),原因是此宽度下 L 的探针估计低估约 8 倍
   (自适应保护机制的 L_scale_final = 8 就是证人),而按论文规定
   算法 1 没有保护机制。提高 r 反而进一步摊薄每节点的打磨步数
   (同一保险丝分给更多节点),救不了这一层。

r 从 10 提到 20(复验):**前沿**确实按"加密 λ 菜单"的直觉改善了
(8 个交付点,多段贴上自适应前沿),但证书没有——按审计公式也
不可能——被救回。前沿量的是交付点的函数值;证书量的是对**所有**
权重的最坏梯度范数。它们是不同的量,这个实验把两者都展示了。

**总体结论。**在这个梯度昂贵的测试台上,认证模式下,自适应方法
交付的帕累托菜单更密、更光滑、且在权衡内部区域支配基线,认证成本
分别只有梯度保险丝的 6.6%(ε 0.01)和 35%(ε 0.001);而均匀网格
基线在两个网格分辨率下都烧完保险丝、并因两层独立的原因认证失败。
r 扫描进一步量化了基线要认证 ε 0.01 需要什么:约 r ≈ 62 的网格
(对半分口径),**加上**解决中间节点步长脆弱性的手段——也就是
远多于现在的预算,和一个论文的算法 1 并不具备的保护机制。

诚实报告说明:自适应证书的证人是它自己的 8 起点搜索(NP 难最大化
的启发式下界);prune_inner=True 使 ε 模式收敛时间证明的条件不
满足(每个 summary.json 里都记录了该警告),但不影响停止规则;
D 是运行后在交付点处测得(每节点一次求值,展示级开销);单一问题
实例、种子 7/8——结论是跨运行的模式,不是精确的比值本身。
