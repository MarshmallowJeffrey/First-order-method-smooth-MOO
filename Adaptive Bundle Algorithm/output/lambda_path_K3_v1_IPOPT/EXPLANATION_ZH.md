# 机制分析:自适应束方法的 λ 为什么长这样

日期:2026 年 7 月 9 日。配套:同文件夹的三张图与数据——
`lambda_path_triangle.png`(主图:三角形上的两类移动),
`lambda_step_sizes.png`(逐轮步长与收缩趋势),
`lambda_path_quarters.png`(按时间四分段的小三角形),
`summary.json`(全部 λ 序列和统计),`README.md`(英文规格)。
运行配置 = 平台实验 K=3 的原配置改为**认证模式**(ε=0.001,
30,000 次梯度的预算保留为保险丝);图中蓝色空心圆是基线在 r=10 下的
66 个均匀网格节点——由 (K, r) 纯组合决定,不需要运行基线;
橙色实心点是自适应方法逐轮选出的权重。

**本次运行的结局:第 180 轮认证停止,共用 13,155 次梯度
(保险丝的 44%),停止时刻自己搜索到的最坏值 6.57e-4 ≤ 2ε/3。**

本文的目的是把两条直觉("λ 点与点之间不均匀"、"满足 ε 之前可以选
很多个 λ")打磨成精确的机制陈述,并诚实地回答:期望中的
"连续的线"在多大程度上成立。

## 1. 每一轮的 λ 是什么:诊断结果,不是采样

每个外层轮次开始时,算法解

    λ_t = argmax_λ [ min_i ‖∇F_λ(x_i)‖² ]

——在当前束(已算过的所有点)下,**哪个权重被服务得最差,λ 就落在哪**。
所以这串 λ 不是从什么分布里"采"出来的,而是逐轮的**最坏处坐标记录**。
基线的 66 个红点在看到问题之前就定死了;紫色序列的每一个点都由问题
当场决定。这是两种预算分配哲学的可视化:均匀摊开 对 哪里最坏去哪里。

## 2. 为什么 λ 必然移动:自我熄灭

在 λ_t 处做完内层步后,新加进束的点 x_new 满足 ‖∇F_{λ_t}(x_new)‖
很小。GN(λ) = min_i ‖∇F_λ(x_i)‖² 里每一支都是 λ 的二次型(连续),
所以这个新点不只压低 λ_t 一个点,而是在 λ_t 周围压出一片**洼地**。
下一轮的 argmax 于是必然离开刚服务过的邻域——同一个权重不会连续
两轮都是最坏。这就是"点与点之间不均匀"的根源:序列的每一步都被
上一步**排斥**出它刚工作过的区域。

## 3. 什么时候像"连续的线":局部滑动

一轮只往束里加一个点(prune_inner=True),GN 地形只在被服务的邻域内
被改动,其余区域的高地原样保留。当剩余地形的最高点恰好在新洼地的
**边缘**时,argmax 就"滑"到旁边——图上表现为相邻轮次的 λ 挨在一起、
形成局部短链。λ 搜索的温启动(上一轮的 λ 是 64 个起点之一)也在
近平台地形里偏向邻近的极大点。

**在图上怎么看**:主图 `lambda_path_triangle.png` 里,凡相邻两轮的
L1 距离小于 0.2(网格间距的 2 倍)的移动画成**橙色粗线段**——这些
就是局部短链,散布全图、一眼可见;≥ 0.2 的移动画成浅灰细线(跳跃,
刻意淡化)。本次运行 23% 的步是链步,51% 的步小于 0.5。

**收缩趋势看 `lambda_step_sizes.png` 与 `lambda_path_quarters.png`**:
四个时间段的平均步长为 0.93 → 0.58 → 0.36 → 0.57,链步占比
2% → 25% → 43% → 25%。前三段单调收缩:覆盖越完善,剩下的高地越小
越破碎,滑动越多、跳越短。第四段的**反弹是真实且有信息量的**:
接近达标时,只剩几个**彼此分散**的超标小口袋(看第四个小三角形:
链集中在左下和右缘两处),算法在口袋**之内**滑动打磨、在口袋
**之间**中距离跳跃,于是平均步长回升而链步仍多。滚动中位数在最后
约 20 轮降到 0.25 以下——收尾时几乎只剩局部打磨。

## 4. 什么时候跳:全局重分配

当三角形另一头的高地更高时,64 起点的全局搜索直接跳过去——
主图中的浅灰细线就是这些跳跃:中位步长 0.47(网格间距的 4.7 倍),
最大步长 2.0(整个单纯形的 L1 直径);`lambda_step_sizes.png` 里
灰色柱是跳、橙色柱是链,开头约 40 轮几乎全是长跳(第一段链步只占
2%——起步阶段是对整个三角形的大范围侦察)。**跳跃不是缺陷,而是自适应性最直接的证据**:预算在一轮
之内瞬时转移到新的最坏区域。基线做不到这件事——它必须按网格顺序
把每个节点的份额走完,不管那个节点还需不需要。

所以对"期望结果是连续的线"的诚实修正:**真实图景是
"局部短链 + 全局跳跃"的自适应覆盖序列**,且随覆盖完善,链越来越多、
跳越来越短。"一条连续的线"只在最坏区域恰好逐步平移时局部出现。

## 5. ε 的角色:你的第二条直觉的精确化(本次有实测)

"满足 ε 之前应该可以选很多个 λ"的准确说法是:

**在 ε 模式下,"还没满足 ε" 恰恰等价于 "三角形里仍存在
GN > 2ε/3 的权重";只要这样的权重存在,下一轮的 argmax 就必然找到
一个。所以序列不是"可以选很多 λ",而是"被迫逐个访问所有仍然超标的
区域,直到一个不剩"——停止的那一刻,就是覆盖完成的证书。**

本次运行正是这样结束的:第 180 轮的搜索只找到 6.57e-4 ≤ 2ε/3,
再无超标之处,于是停止——只花了保险丝预算的 44%。这同时演示了
认证模式对预算模式的实际意义:预算模式会把剩下的 56% 继续花在
已经达标的问题上。

## 6. 不均匀密度:难的地方去得多

180 轮落在 156 个边长 0.05 的胞里(有回访但不多——认证一达标就停,
不像预算模式那样反复打磨);访问位置的分布:76% 在三角形内部,
24% 在边上(min λ < 0.02),5% 在顶点附近(max λ > 0.9)。
对照基线:66 个节点,每个节点分同样的预算,不看难度。
**自适应方法的"打点密度"是问题难度的地图;基线的打点密度是一个
常数。**

## 7. 一句话总结

基线把 λ 当成**事先固定的网格**;自适应方法把 λ 当成**逐轮更新的
诊断**——每轮去当前最坏处,服务完就把那里熄灭,序列以"局部滑动 +
全局跳跃"的方式自适应地覆盖整个权重域,难处密、易处疏,
直到再无超标之处、在第 180 轮持证停止。
